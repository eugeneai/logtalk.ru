До сих пор мы писали программы, которые знают о своих объектах на этапе загрузки. Но иногда программе нужно **исследовать саму себя**: узнать, какие объекты загружены, какие предикаты они объявляют, кто наследует кого и какие протоколы реализует объект. Такая возможность называется **рефлексией**.

Logtalk поддерживает два вида рефлексии:

- **структурную** — запросы о строении программы: объектах, категориях, протоколах, предикатах и их свойствах;
- **поведенческую** — наблюдение за сообщениями, которые объекты посылают друг другу во время работы программы.

В этой части мы сосредоточимся на структурной рефлексии. Поведенческая рефлексия рассматривается в части 9, где изучается перехват сообщений.

## Перечисление объектов

Встроенный предикат `current_object/1` перечисляет все загруженные объекты:

```logtalk
?- current_object(Object).
Object = logtalk ;
Object = user ;
...
```

Если передать конкретное имя, предикат проверит, существует ли такой объект:

```logtalk
?- current_object(class).
true.

?- current_object(no_such_object).
false.
```

Аналогично работают `current_protocol/1` и `current_category/1` для протоколов и категорий.

Собрать все объекты в список можно через `findall/3`:

```logtalk
?- findall(Object, current_object(Object), Objects).
Objects = [logtalk, user, ...].
```

Порядок объектов не определён, поэтому не стоит полагаться на него в тестах.

## Свойства объектов

Предикат `object_property/2` возвращает свойства объекта. Например, список публичных предикатов:

```logtalk
?- object_property(counter, public(Predicates)).
Predicates = [value/1, increment/0].
```

Другие полезные свойства:

- `static` — объект статический;
- `dynamic` — объект динамический и может быть уничтожен;
- `built_in` — встроенный объект;
- `file(Path)` — файл, в котором определён объект;
- `defines(Predicate, Properties)` — свойства определённого предиката;
- `declares(Predicate, Properties)` — свойства объявленного предиката.

Например, чтобы узнать, где определён предикат `value/1`:

```logtalk
?- object_property(counter, defines(value/1, Properties)).
Properties = [lines(96, 101), number_of_clauses(1), ...].
```

Свойства с номерами строк доступны только при компиляции с флагом `source_data(on)`, который включён по умолчанию.

## Прозрачное и чёрное представление

Logtalk различает два взгляда на структуру программы:

- **прозрачное** (transparent-box) — видны все объявления, определения, вызовы и даже номера строк;
- **чёрное** (black-box) — видны только те предикаты, которые доступны с точки зрения текущего объекта.

`object_property/2`, `current_object/1`, `current_protocol/1` и `current_category/1` относятся к прозрачному представлению. Они позволяют инструментам анализировать программу целиком.

Чёрное представление используется, когда нужно узнать, какие сообщения можно отправить объекту. Для этого служат методы `current_predicate/1` и `predicate_property/2`, вызываемые в контексте объекта. Например, для объекта-прототипа:

```logtalk
:- object(prototype_example).

    :- public(hello/1).
    hello(world).

:- end_object.
```

```logtalk
?- prototype_example::current_predicate(Predicate).
Predicate = hello/1.
```

Такой запрос учитывает инкапсуляцию: приватные предикаты другого объекта не будут видны. Для класса `current_predicate/1` перечисляет предикаты, видимые его экземплярам; чтобы получить объявления самого класса, используйте `object_property/2`.

## Отношения между объектами

Для анализа иерархии классов используются уже знакомые предикаты:

```logtalk
?- instantiates_class(Object, Class).
?- specializes_class(Class, Superclass).
?- implements_protocol(Object, Protocol).
?- extends_object(Object, Parent).
?- imports_category(Object, Category).
```

Например, можно найти все классы, которые специализируют `object`:

```logtalk
?- findall(Class, specializes_class(Class, object), Classes).
Classes = [abstract_class, ...].
```

## Рефлексия и инструменты разработки

Структурная рефлексия — основа инструментов Logtalk: отладчика, генератора документации, анализатора мёртвого кода и системы тестирования. Все они являются обычными Logtalk-приложениями и используют те же встроенные предикаты, которые доступны вашей программе.

В следующем разделе мы научимся управлять компилятором и загрузкой файлов, а затем создадим собственные генераторы экземпляров.
