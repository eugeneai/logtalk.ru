<text-box variant='learningObjectives' name="Цель изучения раздела">

После изучения этого раздела вы сможете

- Загружать и компилировать исходные файлы Logtalk
- Писать файлы-загрузчики (`loader.lgt`)
- Управлять флагами компилятора
- Перезагружать изменённые файлы через `logtalk_make/0-1`

</text-box>

Logtalk-программа состоит из исходных файлов с объектами, категориями и протоколами. Чтобы они стали доступны, файлы нужно скомпилировать и загрузить в память. Этим управляют встроенные предикаты `logtalk_compile/1-2`, `logtalk_load/1-2` и `logtalk_make/0-1`.

## Компиляция и загрузка

`logtalk_compile/1` компилирует файл в промежуточный Prolog-файл, но не загружает его:

```logtalk
?- logtalk_compile('Set6.lgt').
```

`logtalk_load/1` компилирует файл и сразу загружает его:

```logtalk
?- logtalk_load('Set6.lgt').
```

Можно передать список файлов:

```logtalk
?- logtalk_load(['Set5.lgt', 'Set6.lgt']).
```

Если расширение `.lgt` стандартное, его можно опустить.

## Файл-загрузчик

Для проекта удобно создать файл `loader.lgt`, который загружает все нужные файлы и настраивает флаги:

```logtalk
:- initialization((
    set_logtalk_flag(report, warnings),
    logtalk_load(['Set5.lgt', 'Set6.lgt'])
)).
```

Затем достаточно выполнить:

```logtalk
?- logtalk_load('loader.lgt').
```

Файлы-загрузчики — обычные исходные файлы Logtalk. В них можно задавать глобальные операторы, флаги проекта и пути к библиотекам.

## Перезагрузка изменённых файлов

Во время разработки удобно использовать `logtalk_make/0`:

```logtalk
?- logtalk_make.
```

Он перезагружает все изменённые исходные файлы. Расширенная версия `logtalk_make/1` принимает цель:

```logtalk
?- logtalk_make(check).       % проверить проект
?- logtalk_make(clean).       % удалить промежуточные файлы
?- logtalk_make(debug).       % перезагрузить в режиме отладки
?- logtalk_make(normal).      % обычный режим
?- logtalk_make(optimal).     % оптимизированный режим
```

Цели `debug`, `normal` и `optimal` меняют режим компиляции всех файлов проекта.

## Флаги компилятора

Флаги управляют поведением компилятора. Текущее значение можно узнать так:

```logtalk
?- current_logtalk_flag(report, Value).
Value = warnings.
```

Установить новое значение:

```logtalk
?- set_logtalk_flag(report, off).
```

Часто используемые флаги:

- `report(on | warnings | off)` — вывод сообщений компилятора;
- `source_data(on | off)` — сохранять данные об исходном коде;
- `optimize(on | off)` — оптимизация;
- `debug(on | off)` — режим отладки;
- `unknown_entities(warning | silent)` — предупреждения о неизвестных объектах;
- `events(allow | deny)` — поддержка событий;
- `dynamic_declarations(allow | deny)` — динамическое объявление предикатов.

Флаг можно задать для всего проекта, для файла или для отдельного объекта:

```logtalk
:- set_logtalk_flag(unknown_entities, silent).

:- object(my_object).

    :- set_logtalk_flag(events, allow).

    ...

:- end_object.
```

Область действия директивы `set_logtalk_flag/2` ограничена файлом или объектом.

## Пользовательские флаги

Если инструменту или библиотеке нужен собственный флаг, его можно создать:

```logtalk
?- create_logtalk_flag(my_flag, 42, [type(integer), keep(true)]).
true.

?- current_logtalk_flag(my_flag, Value).
Value = 42.
```

Флаг `keep(true)` означает, что значение сохраняется при перезагрузке файлов.

## Настройки проекта

Глобальные настройки удобно хранить в файле `settings.lgt` в каталоге проекта или в домашнем каталоге Logtalk. В нём обычно находится директива `initialization/1` с вызовами `set_logtalk_flag/2` и определениями `logtalk_library_path/2`.

Не путайте:

- `set_logtalk_flag/2` как **директива** действует на файл или объект;
- `set_logtalk_flag/2` как **встроенный предикат** меняет глобальные значения на время сеанса;
- `settings.lgt` загружается при старте Logtalk и задаёт значения по умолчанию.

## Что важно запомнить

- `logtalk_compile/1` компилирует, `logtalk_load/1` компилирует и загружает.
- `logtalk_make/0-1` перезагружает изменённые файлы и меняет режим компиляции.
- Флаги задаются директивами в файлах и объектах или глобально через встроенный предикат.
- Для проекта нужен свой `loader.lgt`, а для общих настроек — `settings.lgt`.
