Модельно-управляемая разработка редко состоит из одного шага. Обычно модель проходит несколько **преобразований**:

```text
исходная модель → проверенная модель → промежуточное представление → код
```

## Преобразование

Преобразование — это обычный предикат, который принимает одну структуру и возвращает другую:

```logtalk
:- object(transformer).
    :- public(entity_to_spec/2).

    entity_to_spec(entity(Name, Fields, Relations),
                   object_spec(Name, Fields, Relations)).

:- end_object.
```

```logtalk
?- transformer::entity_to_spec(
       entity(person, [name, age], []),
       Spec).
Spec = object_spec(person, [name, age], []).
```

Такое преобразование легко тестировать отдельно от генерации кода.

## Цепочка

```logtalk
generate(Entity, Code) :-
    course_model::entity(Entity, Fields, Relations),
    transformer::entity_to_spec(
        entity(Entity, Fields, Relations),
        Spec),
    validator::check(Spec),
    codegen::render(Spec, Code).
```

Каждый шаг отвечает за одну задачу:

- `course_model` хранит модель;
- `transformer` меняет представление;
- `validator` проверяет ограничения;
- `codegen` создаёт текст.

Если генерация сломалась, проще найти шаг, на котором испортились данные.

## Hook-объекты

Hook-объект может перехватывать раскрытие термов и целей. Это позволяет встроить предметно-ориентированный язык прямо в исходный файл:

```logtalk
:- object(mda_hook,
    implements(expanding)).

    term_expansion(entity(Name, Fields),
                   object(Name, [], [public(fields/1)], [fields(Fields)])).

:- end_object.
```

Подключение:

```logtalk
?- logtalk_load(mda_hook).
?- logtalk_load('model.lgt', [hook(mda_hook)]).
```

Теперь конструкция `entity(person, [name, age]).` в модели превращается в объект на этапе компиляции. Это удобно, но требует осторожности: ошибки раскрытия сложнее диагностировать.

## Трассируемость

Хорошая MDA-система хранит связь между элементом модели и сгенерированным кодом. Например, в комментарии к объекту можно указать:

```logtalk
% generated from entity(person)
```

Тогда при изменении модели понятно, какой код нужно перегенерировать.

## Проверка перед генерацией

Минимальные проверки:

- все ссылки на сущности существуют;
- имена уникальны;
- типы атрибутов известны;
- нет циклических обязательных связей;
- модель не пуста.

Лучше остановить генерацию с понятной ошибкой, чем создать код, который не компилируется.

## Что важно запомнить

- Преобразование модели — обычный предикат.
- Цепочка преобразований разделяет проверку, трансформацию и генерацию.
- Hook-объекты позволяют встроить DSL в исходные файлы.
- Ошибки раскрытия сложнее отлаживать, чем явные преобразования.
- Храните связь между моделью и сгенерированным кодом.
