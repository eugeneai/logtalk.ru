Обычный адаптер реализует каждый метод протокола явно. Если методов много, писать обёртки для каждого утомительно. **Прокси** пересылает сообщения исходному объекту автоматически.

## Пересылка через forward/1

Logtalk вызывает метод `forward/1`, когда объект получает сообщение, для которого нет объявления. Чтобы включить этот механизм, объект реализует протокол `forwarding`:

```logtalk
:- object(proxy(_Source_),
    implements(forwarding)).

    forward(Message) :-
        [_Source_::Message].

:- end_object.
```

Теперь любое неизвестное сообщение, отправленное прокси, будет делегировано источнику:

```logtalk
?- proxy(plain_text(hello))::text(Text).
Text = hello.
```

Конструкция `[_Source_::Message]` — это **делегирование**. Она сохраняет исходного отправителя и контекст мета-вызова. Если использовать обычное `_Source_::Message`, отправителем станет сам прокси, что иногда меняет поведение мета-предикатов.

## Прокси с дополнительным поведением

Прокси может перехватывать часть сообщений, а остальные пересылать:

```logtalk
:- object(logging_proxy(_Source_),
    implements(forwarding)).

    :- public(log/1).
    log(Message) :-
        write(Message), nl.

    forward(Message) :-
        log(request(Message)),
        [_Source_::Message].

:- end_object.
```

Здесь каждое пересланное сообщение попадает в журнал. Источник об этом не знает.

## Прокси и инкапсуляция

Прокси может ограничивать доступ:

```logtalk
:- object(read_only_proxy(_Source_),
    implements(forwarding)).

    forward(Message) :-
        allowed(Message),
        [_Source_::Message].

    allowed(read(_)).

:- end_object.
```

Сообщения, не прошедшие проверку, просто не пересылаются. Это пример контроля доступа на уровне сообщений.

## Ограничения

- `forward/1` срабатывает только для сообщений, которые не объявлены в самом прокси.
- Прокси не должен скрывать ошибки: неудачная пересылка выглядит как неудача сообщения.
- Слишком «умный» прокси усложняет отладку: сообщение проходит через несколько слоёв.
- Для типизированного интерфейса лучше явно реализовать протокол, а `forward/1` использовать для расширяемых объектов.

## Прокси или адаптер?

- **Адаптер** явно преобразует интерфейс и данные.
- **Прокси** сохраняет интерфейс и добавляет поведение вокруг вызова.

Если нужно изменить форму данных — используйте адаптер. Если нужно добавить логирование, кэширование или контроль доступа, не меняя интерфейс, — используйте прокси.

## Что важно запомнить

- `forward/1` пересылает неизвестные сообщения.
- `[Object::Message]` делегирует сообщение с сохранением контекста.
- Прокси удобен для логирования, кэширования и контроля доступа.
- Прокси не заменяет явный адаптер, когда нужно преобразование интерфейса.
