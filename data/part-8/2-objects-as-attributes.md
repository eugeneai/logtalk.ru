В части 8/1 мы познакомились с компонентами `file` и `catalog`. Компонент предоставляет интерфейс (протокол) и реализует его. Но в реальных системах компоненты редко совпадают по интерфейсам идеально. Тогда между ними ставят **адаптер** — объект, который принимает сообщения одного интерфейса и переводит их в сообщения другого.

## Интерфейс компонента

Начнём с простого протокола:

```logtalk
:- protocol(text_p).

    :- public(text/1).

:- end_protocol.
```

Компонент `plain_text` хранит текст в параметре и реализует протокол:

```logtalk
:- object(plain_text(_Text_),
    implements(text_p)).

    text(_Text_).

:- end_object.
```

Запрос:

```logtalk
?- plain_text(hello)::text(Text).
Text = hello.
```

Параметр `_Text_` — это параметрическая переменная объекта. Она доступна всем предикатам объекта и играет роль его параметра.

## Адаптер

Пусть есть компонент, который умеет возвращать текст, но нам нужен текст в верхнем регистре. Вместо изменения компонента напишем адаптер:

```logtalk
:- object(uppercase_adapter(_Source_),
    implements(text_p)).

    text(Upper) :-
        _Source_::text(Text),
        upcase_atom(Text, Upper).

:- end_object.
```

Адаптер сам реализует `text_p`, поэтому его можно использовать везде, где ожидается компонент с этим интерфейсом:

```logtalk
?- uppercase_adapter(plain_text(hello))::text(Text).
Text = 'HELLO'.
```

Важно: `plain_text` не знает об адаптере, а адаптер не меняет `plain_text`. Компонент и адаптер развиваются независимо.

## Зачем нужны адаптеры

- **Совместимость.** Старый компонент можно подключить к новой системе, не переписывая его.
- **Повторное использование.** Один и тот же компонент используется с разными адаптерами.
- **Инкапсуляция.** Детали преобразования скрыты внутри адаптера.
- **Тестируемость.** Адаптер можно протестировать отдельно от компонента.

## Адаптер и наследование

Адаптер не обязан наследовать компонент. Он **делегирует** работу источнику через сообщение `_Source_::text(Text)`. Это композиция, а не наследование. В Logtalk композиция часто предпочтительнее множественного наследования: она проще и не создаёт хрупких иерархий.

## Связь с Haskell

В Haskell адаптер можно сравнить с функцией-обёрткой:

```haskell
uppercaseAdapter :: TextComponent -> TextComponent
uppercaseAdapter source = source { getText = map toUpper (getText source) }
```

В Logtalk адаптер — объект с состоянием и поведением, но идея та же: не менять исходный компонент, а обернуть его в новый слой.

## Что важно запомнить

- Протокол описывает интерфейс компонента.
- Компонент реализует протокол.
- Адаптер реализует тот же протокол, но делегирует работу другому компоненту.
- Адаптеры позволяют соединять компоненты без изменения их кода.
