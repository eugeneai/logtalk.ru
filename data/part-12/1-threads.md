- Включать поддержку потоков в объекте
- Выполнять несколько целей параллельно через `threaded/1`
- Запускать цель асинхронно и получать результат
- Понимать, когда параллельность действительно полезна

Logtalk поддерживает многопоточность на backend-компиляторах, которые предоставляют совместимые примитивы. Для SWI-Prolog флаг `threads` имеет значение `supported`.

## Включение потоков в объекте

Прежде чем вызывать потоковые предикаты, объект должен объявить это директивой:

```logtalk
:- object(parallel_demo).
    :- threaded.
    % методы, которые используют потоки
:- end_object.
```

Без `:- threaded.` компилятор может отклонить вызовы `threaded/1`, `threaded_call/1` и связанных предикатов.

## Параллельное выполнение целей

`threaded/1` запускает каждую цель из конъюнкции в отдельном потоке и ждёт завершения всех потоков:

```logtalk
:- object(parallel_demo).
    :- threaded.

    :- public(sum_squares/3).

    sum_squares(A, B, Sum) :-
        threaded((
            square(A, SA),
            square(B, SB)
        )),
        Sum is SA + SB.

    square(N, Square) :-
        Square is N * N.

:- end_object.
```

```logtalk
?- parallel_demo::sum_squares(3, 4, Sum).
Sum = 25.
```

Если цели независимы и достаточно дороги, `threaded/1` может сократить время вычислений. На маленьких задачах накладные расходы на создание потоков могут быть больше выигрыша.

## Дизъюнкция: гонка методов

Если аргумент `threaded/1` — дизъюнкция, цели конкурируют. Первая успешная цель завершает остальные:

```logtalk
solve(Problem, Solution) :-
    threaded((
        method_a(Problem, Solution)
    ;   method_b(Problem, Solution)
    ;   method_c(Problem, Solution)
    )).
```

Это удобно, когда заранее неизвестно, какой алгоритм быстрее или какой вообще сойдётся.

## Асинхронный запуск

`threaded_call/1` запускает цель и сразу возвращает управление. Результат забирают через `threaded_exit/1`:

```logtalk
:- object(async_demo).
    :- threaded.
    :- use_module(library(lists), [member/2]).

    :- public(first_member/2).

    first_member(List, X) :-
        threaded_once(member(X, List)),
        threaded_exit(member(X, List)).

:- end_object.
```

```logtalk
?- async_demo::first_member([a, b, c], X).
X = a.
```

`threaded_once/1` оставляет только первое решение. Если нужны все решения, используют `threaded_call/1` и несколько вызовов `threaded_exit/1`.

## Варианты с тегом

`threaded_call(Goal, Tag)` возвращает тег запуска. Тот же тег передают в `threaded_exit(Goal, Tag)`, если в объекте одновременно работает несколько одинаковых целей:

```logtalk
threaded_call(worker(1), Tag),
threaded_call(worker(2), Tag2),
threaded_exit(worker(1), Tag),
threaded_exit(worker(2), Tag2).
```

Тег — непрозрачный терм; не полагайтесь на его внутреннюю структуру.

## Когда использовать потоки

- Независимые вычисления: параллельная обработка списка, загрузка данных, расчёты.
- Конкурирующие алгоритмы: несколько методов решения одной задачи.
- Фоновые задачи: асинхронная запись, серверные обработчики.

Не используйте потоки для простых операций и для доступа к общим изменяемым данным без синхронизации.

## Что важно запомнить

- `:- threaded.` включает потоковые вызовы в объекте.
- `threaded/1` выполняет конъюнкцию целей параллельно и ждёт завершения.
- Дизъюнкция в `threaded/1` означает конкуренцию целей.
- `threaded_call/1` запускает асинхронно, `threaded_exit/1` забирает результат.
- `threaded_once/1` оставляет только первое решение.
