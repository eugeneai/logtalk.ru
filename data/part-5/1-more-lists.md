В Logtalk нет отдельного ключевого слова `class`. Класс, экземпляр и прототип — это **роли**, которые объект играет в зависимости от своих отношений с другими объектами. Объект, у которого нет отношений наследования или создания экземпляров, считается прототипом. Если объект объявлен как экземпляр другого объекта, он играет роль экземпляра, а объект, который он создаёт, — роль класса.

Эта идея отличается от классов в Haskell. В Haskell конструкция `class` описывает набор операций над типами, а `instance` — реализацию этого набора для конкретного типа. В Logtalk класс — это обычный объект, который может хранить методы, наследовать другие объекты и создавать экземпляры. Поэтому классы и экземпляры в Logtalk существуют во время выполнения программы и являются такими же объектами, как и все остальные.

## Корневые классы

Чтобы работать с классами, нужна точка отсчёта — корневые объекты иерархии. В официальном учебнике Logtalk используется следующая схема:

```logtalk
:- set_logtalk_flag(unknown_entities, silent).

:- object(object,
    instantiates(class)).
:- end_object.

:- object(abstract_class,
    instantiates(class),
    specializes(object)).
:- end_object.

:- object(class,
    instantiates(class),
    specializes(abstract_class)).

    :- public(new/1).
    new(Instance) :-
        self(Class),
        create_object(Instance, [instantiates(Class)], [], []).

:- end_object.
```

Здесь:

- `object` — корень иерархии, содержащий методы, общие для всех объектов;
- `abstract_class` — класс, от которого наследуются абстрактные классы;
- `class` — метакласс, содержащий метод `new/1` для создания экземпляров.

Все три объекта одновременно являются классами и экземплярами класса `class`. Это рефлексивная система: класс — тоже объект, поэтому у него есть собственный класс. Флаг `unknown_entities` отключён, потому что объекты ссылаются друг на друга до того, как все они определены.

В большинстве учебных программ достаточно упрощённого варианта: метакласс `class` является экземпляром самого себя. Такой вариант короче, но менее гибок:

```logtalk
:- object(class,
    instantiates(class)).

    :- public(new/1).
    new(Instance) :-
        self(Class),
        create_object(Instance, [instantiates(Class)], [], []).

:- end_object.
```

## Определение класса

Определим класс `greeter`, который умеет здороваться с именем:

```logtalk
:- object(greeter,
    instantiates(class),
    specializes(object)).

    :- public(hello/1).
    hello(Name) :-
        format('Hello, ~w!~n', [Name]).

:- end_object.
```

Разберём объявление:

- `instantiates(class)` делает `greeter` экземпляром метакласса `class`, поэтому `greeter` наследует метод `new/1`;
- `specializes(object)` делает `greeter` классом-наследником `object`;
- `hello/1` объявлен публичным, поэтому его можно вызвать извне.

Теперь можно создать экземпляр и отправить ему сообщение:

```logtalk
?- greeter::new(G), G::hello('world').
Hello, world!
G = ...
true.
```

Метод `new/1` создаёт **динамический объект** `G`, который является экземпляром класса `greeter`. Такой объект существует только во время текущего сеанса Logtalk.

## Статические экземпляры

Экземпляр можно объявить и в исходном файле, как обычный объект:

```logtalk
:- object(alice,
    instantiates(greeter)).
:- end_object.
```

Такой экземпляр называется статическим: он загружается вместе с программой и не может быть уничтожен вызовом `abolish_object/1`.

## Проверка отношений

Logtalk предоставляет встроенные предикаты для проверки отношений между объектами:

```logtalk
?- instantiates_class(alice, Class).
Class = greeter.

?- specializes_class(greeter, Superclass).
Superclass = object.
```

Для получения свойств объекта можно использовать `object_property/2`:

```logtalk
?- object_property(greeter, public(Predicates)).
Predicates = [hello/1].
```

Эти запросы полезны при отладке: они показывают, действительно ли объект является классом или экземпляром, и какие методы он объявляет.

## Что важно запомнить

- Класс в Logtalk — это объект с отношениями `instantiates` и/или `specializes`.
- Чтобы создавать экземпляры, нужен метакласс с методом `new/1`.
- Экземпляры могут быть статическими (объявлены в файле) или динамическими (созданы через `new/1` или `create_object/4`).
- Отношения между объектами можно проверить предикатами `instantiates_class/2` и `specializes_class/2`.
