Не все нештатные ситуации являются ошибками программы. Например, «товара нет на складе» — это ожидаемый результат, а не сбой. Для таких случаев полезно проектировать отдельные термы или использовать библиотеку `expecteds`.

## Свои исключения

Собственное исключение — это обычный терм с понятной структурой:

```logtalk
:- object(inventory).
    :- public(reserve/2).

    reserve(Item, Quantity) :-
        stock(Item, Available),
        ( Available >= Quantity ->
            New is Available - Quantity,
            update_stock(Item, New)
        ;   throw(error(insufficient_stock(Item, Available, Quantity), reserve/2))
        ).

    stock(apple, 10).
    stock(pear, 0).

    update_stock(Item, Quantity) :-
        retractall(stock(Item, _)),
        assertz(stock(Item, Quantity)).

    :- dynamic(stock/2).

:- end_object.
```

Обработчик может разобрать этот терм и показать пользователю понятное сообщение:

```logtalk
handle(error(insufficient_stock(Item, Have, Want), _)) :-
    format('Недостаточно ~w: есть ~w, нужно ~w~n', [Item, Have, Want]).
```

## Когда исключение уместно

Используйте исключение, если:

- вызов нарушает контракт предиката;
- продолжение работы невозможно;
- ошибка должна дойти до верхнего уровня;
- нужен стек контекста.

Не используйте исключение для обычного ветвления, если ситуация ожидаема и её можно обработать локально.

## `expecteds`

Библиотека `expecteds` представляет результат как «ожидаемое значение» или «неожидаемая ошибка»:

```logtalk
:- object(expected_demo).
    :- public(safe_div/3).

    safe_div(A, B, Expected) :-
        ( integer(B), B =\= 0 ->
            Q is A / B,
            expected::of_expected(Q, Expected)
        ;   expected::of_unexpected(division_by_zero(B), Expected)
        ).

:- end_object.
```

```logtalk
?- logtalk_load(expecteds(loader)),
   expected_demo::safe_div(10, 0, E),
   expected(E)::or_else(Value, 0).
E = unexpected(division_by_zero(0)),
Value = 0.
```

`expected/1` — параметрический объект. Он позволяет обрабатывать значение, не прерывая вычисление исключением:

```logtalk
expected(E)::map([X, Y]>>(Y is X * 2), Result)
```

## Стратегии обработки

| Стратегия | Когда подходит |
|---|---|
| `fail` | решения нет, и это нормально |
| `throw/1` | нарушен контракт или продолжать нельзя |
| `expecteds` | ошибка — часть нормального потока данных |
| Код возврата | простой API без исключений |
| Лог + значение по умолчанию | ошибка некритична, но важна для диагностики |

Выбирайте стратегию на границе модуля и придерживайтесь её внутри. Смешивание исключений и кодов возврата без документации усложняет сопровождение.

## Что важно запомнить

- Собственное исключение — это терм с понятной структурой.
- Исключения подходят для нарушения контракта и неисправимых ситуаций.
- `expecteds` помогает обрабатывать ожидаемые ошибки без исключений.
- Стратегию обработки выбирайте осознанно и документируйте.
