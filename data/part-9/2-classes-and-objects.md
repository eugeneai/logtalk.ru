После изучения этого раздела вы сможете

- Различать `::/2`, `::/1`, `^^/1` и `[]/1`
- Объяснять, какие вызовы порождают события
- Использовать широковещательную запись сообщений
- Правильно выбирать способ вызова метода

</text-box>

В Logtalk сообщение — это запрос объекту выполнить предикат. Способ отправки сообщения влияет на то, кто считается отправителем, какой контекст используется и генерируются ли события.

## Сообщение другому объекту

```logtalk
?- greeter::hello(world).
```

`::/2` отправляет сообщение `hello(world)` объекту `greeter`. Отправителем считается текущий объект (на верхнем уровне — `user`). Именно этот вызов порождает события `before` и `after`.

## Сообщение самому себе

```logtalk
:- object(counter).

    :- public(increment/0).
    increment :-
        ::read(Value),
        Next is Value + 1,
        ::write(Next).

:- end_object.
```

`::/1` вызывает метод того же объекта (`self`). Такие сообщения не порождают событий: это внутренняя реализация, а не взаимодействие через публичный интерфейс.

## Вызов предка

```logtalk
:- object(step_counter,
    extends(counter)).

    increment :-
        ^^increment.

:- end_object.
```

`^^/1` вызывает унаследованную или импортированную реализацию. Как и `::/1`, этот вызов не порождает событий.

## Делегирование

```logtalk
:- object(proxy(_Source_)).

    forward(Message) :-
        [_Source_::Message].

:- end_object.
```

`[]/1` делегирует сообщение, сохраняя исходного отправителя и контекст мета-вызова. Это важно для мета-предикатов и прокси-адаптеров.

## Широковещательная запись

Если нужно отправить несколько сообщений одному объекту, можно использовать расширенный синтаксис:

```logtalk
?- counter::(read(Value), write(Value)).
```

Это эквивалентно:

```logtalk
?- counter::read(Value), counter::write(Value).
```

Такой синтаксис работает с `,`, `;` и `->`. Он удобен для группировки сообщений, но не меняет семантику: каждое сообщение отправляется отдельно.

## Сравнение способов

| Вызов | Кому | События |
|---|---|---|
| `Object::Message` | другому объекту | да |
| `::Message` | самому себе | нет |
| `^^Message` | предку | нет |
| `[Object::Message]` | делегирование | зависит от контекста |

## События и производительность

Проверка зарегистрированных событий выполняется при каждом `::/2`. Если события не нужны, отключите их для объекта:

```logtalk
:- object(fast_path).

    :- set_logtalk_flag(events, deny).

    ...

:- end_object.
```

Это небольшая, но измеримая оптимизация для горячих участков кода.

## Что важно запомнить

- `::/2` — обычное сообщение другому объекту, оно порождает события.
- `::/1` и `^^/1` — внутренние вызовы без событий.
- `[]/1` сохраняет контекст отправителя и удобен для прокси.
- Широковещательная запись — синтаксический сахар, а не отдельный механизм.
