В распределённой системе клиент отправляет **запрос**, сервер выполняет операцию и возвращает **ответ**. Так работают HTTP API, RPC, очереди задач и многие сетевые протоколы.

## Компоненты

- **Клиент** — инициирует запрос и ждёт результат.
- **Сервер** — принимает запрос, вызывает обработчик и формирует ответ.
- **Транспорт** — способ передачи: HTTP, сокет, очередь сообщений.
- **Формат** — представление данных: JSON, XML, бинарный протокол.

## Запрос и ответ

Минимальный запрос содержит:

- имя операции;
- параметры;
- идентификатор запроса (если ответ нужно сопоставить с запросом).

Ответ содержит:

- идентификатор запроса;
- результат или ошибку.

Пример в JSON:

```json
{"jsonrpc":"2.0","method":"subtract","params":[42,23],"id":1}
```

```json
{"jsonrpc":"2.0","result":19,"id":1}
```

## Уведомления

**Уведомление** — запрос без идентификатора. Сервер выполняет операцию, но не отправляет ответ:

```json
{"jsonrpc":"2.0","method":"log","params":["started"]}
```

Уведомления удобны для событий, журналирования и телеметрии.

## Ошибки

Ошибка должна быть машиночитаемой:

```json
{
  "jsonrpc": "2.0",
  "error": {"code": -32601, "message": "Method not found"},
  "id": 1
}
```

Код ошибки позволяет клиенту обработать ситуацию программно, а сообщение — показать человеку.

## Обработчик

Серверный обработчик обычно:

1. разбирает сообщение;
2. проверяет метод и параметры;
3. вызывает нужную операцию;
4. формирует ответ;
5. отправляет его клиенту.

В Logtalk обработчик можно оформить как объект, реализующий протокол `http_handler_protocol`.

## Что важно запомнить

- Клиент отправляет запрос, сервер возвращает ответ.
- Запрос содержит операцию и параметры, ответ — результат или ошибку.
- Уведомление не требует ответа.
- Ошибки должны иметь код и сообщение.
- Обработчик отделяет транспорт от бизнес-логики.
