Отладчик Logtalk — обычное Logtalk-приложение. Его нужно явно загрузить:

```logtalk
?- logtalk_load(debugger(loader)).
```

Чтобы отладчик мог показывать исходный код, файлы компилируют с флагом `debug(on)`:

```logtalk
?- logtalk_load(my_buggy_code, [debug(on)]).
```

Или глобально:

```logtalk
?- set_logtalk_flag(debug, on).
```

## Трассировка

Запустить трассировку можно так:

```logtalk
?- debugger::trace.
?- my_object::run.
```

Отладчик показывает события четырёх видов:

- **Call** — вызов предиката;
- **Exit** — успешное завершение;
- **Redo** — возврат за новым решением;
- **Fail** — неудача.

Для каждого события можно выполнить команду: продолжить, пропустить вызов, войти внутрь, выйти из предиката и т.п. Точные команды отладчик печатает в приглашении.

## Точки останова

Во время трассировки можно ставить точки останова на конкретные предикаты. Это удобно, когда программа большая, а ошибка возникает только в одном месте.

Команды отладчика работают с сущностями Logtalk, а не с отдельными внутренними предикатами Prolog, поэтому сообщения и вызовы методов выглядят привычно.

## Графический трассировщик SWI-Prolog

Если используется SWI-Prolog, можно задействовать его графический трассировщик:

```logtalk
?- gtrace(foo::bar).
```

Или:

```logtalk
?- gtrace, foo::bar.
```

Для точек останова:

```logtalk
?- gspy(foo::bar/1).
```

Графический трассировщик может показывать внутренние предикаты Logtalk и результат раскрытия макросов. Это нормально: исходный код Logtalk компилируется в Prolog.

## Практические советы

- Сначала попробуйте найти ошибку через тесты и `tutor`.
- Включайте `debug(on)` только для проблемных файлов: отладочный режим замедляет работу.
- Трассируйте конкретное сообщение, а не всю программу.
- После отладки верните обычный режим: `logtalk_make(normal)`.

## Связь с тестированием

Хороший тест сужает место ошибки. Если тест падает, отладчик помогает понять, какое сообщение и какой предикат привели к неудаче. В следующем разделе мы рассмотрим систему тестирования Logtalk.
