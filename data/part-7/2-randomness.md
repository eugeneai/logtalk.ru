<text-box variant='learningObjectives' name="Цель изучения раздела">

После изучения этого раздела вы сможете

- Подключать инструмент `tutor`
- Понимать расширенные сообщения компилятора
- Быстрее находить причины предупреждений и ошибок

</text-box>

Компилятор Logtalk выдаёт сообщения об ошибках и предупреждениях. Начинающему пользователю не всегда понятно, что именно нужно исправить. Инструмент **`tutor`** добавляет к сообщениям пояснения и рекомендации.

## Подключение

```logtalk
?- logtalk_load(tutor(loader)).
```

Обычно `tutor` загружают автоматически при старте, например из `settings.lgt`:

```logtalk
:- initialization(
    logtalk_load(tutor(loader))
).
```

После этого сообщения компилятора становятся подробнее.

## Пример

Без `tutor` предупреждение может выглядеть так:

```text
*     No matching clause for goal: baz(a)
*       while compiling object example
*       in file example.lgt between lines 10-12
```

С `tutor` к нему добавляется объяснение:

```text
*     Calls to locally defined predicates without a clause with a matching head
*     fail. Typo in a predicate argument? Predicate definition incomplete?
```

Это подсказывает, что вызов `baz(a)` не сможет успешно выполниться: для него нет подходящего предложения.

## Когда использовать

`tutor` особенно полезен:

- при изучении Logtalk;
- при разборе новых предупреждений линтера;
- при подключении новых библиотек и инструментов;
- при обучении студентов, которые впервые видят сообщения компилятора.

Для опытных разработчиков `tutor` можно не загружать: сообщения без пояснений короче.

## Связь с другими инструментами

- `help` — справка по языку и библиотекам;
- `tutor` — пояснения к сообщениям компилятора;
- `debugger` — пошаговое выполнение программы;
- `lgtunit` — тестирование.

Эти инструменты дополняют друг друга: `tutor` помогает понять сообщение, `help` — найти описание предиката, `debugger` — разобраться в поведении программы.
