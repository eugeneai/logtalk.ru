Документация в Logtalk хранится рядом с кодом. Это удобно: при изменении предиката легче обновить его описание.

## Документирование сущностей

Для объекта используется директива `info/1`:

```logtalk
:- object(counter).

    :- info([
        version is 1:0:0,
        author is 'Иван Петров',
        date is 2025-05-01,
        comment is 'Счётчик с изменяемым состоянием.'
    ]).

    ...

:- end_object.
```

Для предиката — `info/2` и `mode/2`:

```logtalk
:- object(counter).

    :- public(value/1).
    :- mode(value(-integer), one).
    :- info(value/1, [
        comment is 'Возвращает текущее значение счётчика.',
        argnames is ['Value']
    ]).

:- end_object.
```

`mode/2` описывает направления аргументов:

- `+` — входной аргумент;
- `-` — выходной;
- `?` — может быть входным или выходным;
- `@` — не изменяется.

Второй аргумент `mode/2` — число решений: `one`, `zero_or_one`, `zero_or_more`, `one_or_more` и т.п.

## Генерация документации

Документацию генерирует инструмент `lgtdoc`:

```logtalk
?- logtalk_load(lgtdoc(loader)).
?- lgtdoc::library(my_app).
```

По умолчанию XML-файлы создаются в каталоге `xml_docs`.

Перед генерацией исходные файлы должны быть загружены с `source_data(on)`:

```logtalk
?- logtalk_load(my_app(loader)).
```

Обычно этот флаг задают в загрузчике приложения.

## Преобразование в HTML или Markdown

В поставке Logtalk есть скрипты преобразования XML:

```bash
$ cd xml_docs
$ lgt2html -t "Моё приложение"
```

Или для Markdown:

```bash
$ lgt2md
```

Для HTML нужен XSLT-процессор (`xsltproc`, Xalan или Saxon). Для PDF — XSL-FO-процессор, например Apache FOP.

## Проверки документации

`lgtdoc` предупреждает о проблемах:

- отсутствует `info/1` у объекта;
- отсутствует `info/2` или `mode/2` у предиката;
- в `info/2` не хватает `comment` или `argnames`;
- дата в будущем или в неверном формате;
- в комментарии нет завершающей точки.

Эти предупреждения можно включать и выключать через флаги `lgtdoc_missing_directives`, `lgtdoc_missing_info_key` и другие.

## Автоматизация

Для больших проектов используют инструмент `doclet`, который автоматизирует генерацию документации. Его можно запускать через `logtalk_make(documentation)`.

## Что важно запомнить

- Документация хранится в `info/1`, `info/2` и `mode/2`.
- `lgtdoc` извлекает её через структурную рефлексию.
- XML-файлы преобразуются в HTML, Markdown, PDF и другие форматы скриптами `lgt2*`.
- Хорошая документация начинается с `comment`, `argnames` и корректного `mode/2`.
