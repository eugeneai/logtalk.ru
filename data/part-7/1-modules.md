В части 6 мы познакомились с `logtalk_load/1-2` и флагами компилятора. Теперь соберём эти знания в практический инструмент — файл-загрузчик приложения.

## Зачем нужен загрузчик

По мере роста проекта запускать вручную десятки запросов `logtalk_load/1` неудобно. Вместо этого создают файл `loader.lgt`, который загружает все компоненты в правильном порядке:

```logtalk
:- initialization((
    set_logtalk_flag(report, warnings),
    logtalk_load([
        'domain',
        'services',
        'ui'
    ])
)).
```

Запуск:

```logtalk
?- logtalk_load('loader.lgt').
```

Загрузчик — обычный исходный файл Logtalk. В нём можно задавать флаги, операторы и пути к библиотекам.

## Библиотечные пути

Logtalk умеет искать файлы по именам библиотек. Для этого используется динамический и многофайловый предикат `logtalk_library_path/2`:

```logtalk
:- multifile(logtalk_library_path/2).
:- dynamic(logtalk_library_path/2).

logtalk_library_path(my_app, '$LOGTALKUSER/my_app/').
```

После этого файлы приложения можно загружать через имя библиотеки:

```logtalk
?- logtalk_load(my_app(loader)).
```

Путь в правой части должен заканчиваться разделителем каталога.

## Подключение объектов через uses/2

Директива `uses/2` объявляет, что объект будет обращаться к предикатам другого объекта:

```logtalk
:- object(report_generator).

    :- uses(logger, [log/1, warning/1]).

    generate(Data) :-
        log(start),
        ...

:- end_object.
```

Это не наследование и не импорт категории: объект просто получает короткие имена для вызова чужих предикатов. Директива также помогает компилятору проверять вызовы.

## Включение файлов через include/1

Директива `include/1` вставляет содержимое файла в объект:

```logtalk
:- object(cities).

    :- public(city/2).
    :- include('data/cities.pl').

:- end_object.
```

Так удобно оборачивать большие наборы фактов Prolog в объект, не переписывая их вручную.

## Перезагрузка проекта

Во время разработки:

```logtalk
?- logtalk_make.
```

перезагружает изменённые файлы. Полезные цели:

```logtalk
?- logtalk_make(check).
?- logtalk_make(clean).
?- logtalk_make(documentation).
```

Цель `documentation` запускает генерацию документации, если настроен соответствующий doclet.

## Порядок загрузки

Порядок файлов влияет на оптимизацию. Если объект использует категорию, лучше загрузить категорию раньше. Для сложных проектов можно получить рекомендуемый порядок:

```logtalk
?- logtalk_load(my_app(loader)).
?- logtalk::loaded_files_topological_sort(Sorted).
```

Список `Sorted` помогает упорядочить файлы в загрузчике.

## Что важно запомнить

- `loader.lgt` — центральная точка входа в приложение.
- Библиотечные пути задаются через `logtalk_library_path/2`.
- `uses/2` подключает предикаты другого объекта, `include/1` — содержимое файла.
- `logtalk_make/0-1` перезагружает изменённые файлы и запускает служебные цели.
